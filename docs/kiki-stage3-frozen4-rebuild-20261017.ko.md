## 빌드 경계

Meson 1.9.2와 tomli 2.2.1만 포함한 새 Python 격리 환경을 사용했다. 기존 v1/v2 환경과 빌드 캐시는 유지했다. 호스트 GCC 11.5를 빌드 도구로 사용하고, GNOME 라이브러리의 헤더·링크 입력은 KIKI glibc 2.39 및 Linux UAPI 6.1.187이 있는 후보 sysroot로 고정했다. 기존 gsettings/json 레시피의 glibc 제외 설정을 후보 전용 레시피에서 제거하고 대상 실행 래퍼와 cross file을 적용했다. 공용 레시피와 설치기 소스에는 이번 재빌드 변경을 적용하지 않았다.

공용 빌더가 다른 작업에서 변경돼도 영향을 받지 않도록 이전 후보의 동결 빌더를 사용했다. JSON 테스트 중 GLib가 실행 파일을 다시 실행할 때 호스트 로더로 빠지는 문제가 있어, 최종 14개 테스트는 대상 전용 chroot에서 실행했다. 테스트 제외로 통과 처리하지 않았다.

동결된 설치기 r17은 C/GTK 구현이었다. 작업 폴더의 최신 Go/GTK 번들과 혼동하지 않도록 C 프런트엔드를 다시 컴파일했다. Go 빌드 탐색 결과는 후보 인덱스에 반영하지 않았다. 기존 번들에서 실제 달라진 파일은 프런트엔드 실행 파일과 런타임 메타데이터 두 개이며, 나머지 1,026개 payload 항목은 그대로 유지했다. 스타일 파일은 동결 소스와 기존 payload가 동일했다.

## 인덱스 반영 조건

네 패키지 모두 아카이브 내부 파일의 SHA·크기·모드·심볼릭 링크를 검사하고, 런타임 검증 당시의 패키지 SHA가 그대로인지 확인한다. 패키지 식별자와 레시피 digest도 동결 레시피와 일치해야 한다. 검증이 미완료이거나 네 패키지 중 하나가 누락된 보고서로는 새 후보 인덱스를 만들 수 없음을 확인했다.

새 후보 전체에 대해 124개 패키지의 인덱스 SHA·크기·payload, 런타임 의존성 폐쇄, 소스 SHA와 커널·헤더 6.1.187 고정을 검사한다. 기본 저장소나 기존 후보 인덱스를 새 후보로 자동 전환하지 않는다.

## 남은 검증

검증 범위는 대상 전용 임시 루트와 Xvfb GUI 실행이다. 실제 VM 부팅, 설치 완료, LightDM→GNOME 로그인, Polkit 인증 및 실제 udev 이벤트는 별도 검증이 필요하다. 설치기 번들은 기존 PNG 로고 로더 경고가 남아 있으며, 언어 선택과 본 화면 실행은 통과했다. Xvfb의 DRI3 경고와 GNOME 스키마의 이전 경로 폐기 예정 경고도 기록에 남겼다.

후보는 서명되지 않은 검증용 저장소이며 `release_ready=false` 상태를 유지한다.
