# 관리형 프록시용 웹 응답 후보

이 문서는 이전 배포 기록이다. 이후 사용자가 프록시 관련 기능 제거를 요청하여 [일반 HTTP 웹 서비스](kiki-build-web-http-20261025.ko.md)로 정리했다.

상태: 사용자가 관리형 프록시 모드와 IP·전달 헤더 필수 조건 해제를 명시적으로 승인했고 운영에 적용했다. 인증 서비스만 교체했다.

Terminal Lab이 프록시를 제공하므로 별도 프록시 설치 없이 private HTTP 웹 서비스를 제공하는 구성을 준비했다. 후보 이미지는 `localhost/kiki-build-auth:managed-20261025`이며 호스트 포트 매핑은 기존과 동일하다. 원래 이미지·인증 DB·설정은 보존하며, 이전 설정으로 인증 서비스만 되돌릴 수 있다.

## 변경 내용

- `--managed-proxy`에서 프록시의 출발지 IP가 `10.0.161.214`인지 검사하지 않는다. 공급자 프록시의 주소를 SSH 프록시 주소와 동일하다고 가정하지 않는다.
- HTTPS 전달 헤더가 생략돼도 고정된 공개 HTTPS 주소를 기준으로 로그인·쿠키를 처리한다. 명시적인 HTTP 전달 헤더가 있는 로그인 요청은 공개 HTTPS 주소로 이동한다.
- 인증 없는 `/`는 데이터가 없는 로그인 안내 페이지, `/healthz`는 짧은 정상 응답을 제공한다. 이 경로의 GET·HEAD·OPTIONS 상태 점검에는 쿠키나 특정 Host가 필요하지 않다.
- 로그인과 API의 정확한 Host, HTTPS Origin, Secure·HttpOnly·SameSite 쿠키, 세션, CSRF, 시도 횟수 제한은 유지한다. 패키지·버전·ISO·다운로드와 변경 작업에는 기존 인증이 필요하다.
- 호스트 네트워크 공유나 추가 프록시는 사용하지 않는다. 기존 루프백 8092와 VM 주소 8092 매핑을 유지한다.

## 범위와 위험

현재 클라우드 화면에서 TCP 8092 수신 규칙은 `0.0.0.0/0`로 표시된다. 후보 모드를 적용하면 이 private 주소까지 연결할 수 있는 클라이언트는 특정 출발지 IP 검사 없이 로그인 화면에 접근하고 로그인 시도를 할 수 있다. 계정 인증을 우회해 운영 데이터나 빌드 작업에 접근할 수 있도록 허용하는 변경은 아니다. 공급자 프록시의 정확한 출발지가 확인되면 네트워크 규칙으로 제한할 수 있다.

최초 배포는 자동 승인 검토에서 보안 경계 변경에 명시적 승인이 필요하다는 이유로 거절됐다. 이후 사용자가 해당 변경을 구체적으로 승인하여 최종 배포를 완료했다. 운영 서버에는 별도의 프록시 프로그램을 추가하지 않았다.

## 검증

인증 테스트 34개 통과. 임시 컨테이너에서 기본 HTTP 상태 점검 200, Secure 쿠키, 테스트 계정 로그인, 패키지·버전 API 200을 확인했다. 테스트가 잘못 기대했던 미인증 POST 응답 코드를 실제 정책인 401로 바로잡았으며 운영 코드의 인증 정책은 바꾸지 않았다. 임시 컨테이너는 검증 후 제거했다. 운영 계정의 비밀번호는 조회하거나 변경하지 않았다.

운영에서 IP Host로 보낸 루트·healthz·HEAD·OPTIONS는 200, 공개 도메인 Host로 보낸 일반 HTTP 로그인은 200과 Secure 쿠키, 미인증 API는 401로 확인됐다. 교체 직전·직후 계정·세션 데이터 지문이 같았고, 패키지 빌드 컨테이너 ID와 버전 작업자 PID도 변하지 않았다. 자동 시작 설정을 유지하고 배포된 코드 SHA를 후보 소스와 대조했다.

이 수정이 프록시 503의 원인이라고 확정하지 않았다. 적용 후 공개 HTTP·HTTPS 모두 여전히 503을 반환했다. 터미널랩 화면의 기존 도메인 대상은 `http://10.250.254.229:8092`로 확인했다. 대조 패킷 수집에서는 외부 SSH 경로의 ens3 수신 SYN을 확인했고, 8092 연결은 확인하지 못했다. 120초 웹 전용 수집 통계는 0 captured / 2 received by filter / 0 dropped였으므로 원시 통계를 함께 보존했다. 웹 서비스의 준비 완료와 외부 도메인 접속 복구 완료를 구분한다. 현재 남은 확인 대상은 공급자 서비스의 도메인 연결 경로이며, 별도 프록시 SSH 접속 정보는 필요하지 않다.
