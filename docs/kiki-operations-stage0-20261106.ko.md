# KIKI 독립 운영 화면 — 0단계 점검

점검일: 2026-11-06, Asia/Seoul. 저장소 HEAD: `876554ab8258ce6e0f38c19d0ceed526f26d329a`.
기존 작업 트리의 미완료 변경은 유지했다. 앱·빌드·패키지 코드는 변경하지 않았으며,
이번 산출물은 보존 기준선과 읽기 전용 점검 결과, 이 문서다.

결론: **새 보존 기준선 작성과 기존 기능 점검을 완료했다. 독립 GTK UI 설계·골격 작업에
진입할 수 있지만 incident-ai 전체 연결에는 브라우저 공급이 먼저 필요하다.**
GNOME과 기존 앱을 유지하며, 새 운영 화면의 UI·설정·자동 실행을 셸 확장과 분리하는 방향이다.

## 2. 실제 설치 환경과 저장소 구분

SSH 조회 대상은 독립 시험 VM `kiki-paper-pixel-candidate-r4-20261105`다.
설치된 픽셀 세션 패키지는 r6이며, GNOME Shell/Mutter 50.4와 커널 `6.1.187-kiki-vm`을 사용한다.
호스트의 화면·마우스·키보드를 조작하지 않았고 VM에서도 새 GUI 창을 열지 않았다.

| 기준 | 서명·SHA 결과 | 사용 범위 |
| --- | --- | --- |
| 기존 일반 GNOME 저장소 | 224개 패키지, 런타임 의존성 207개 확인 | 보관된 일반 GNOME 후보 |
| 전체 Paper Pixel r6 저장소 | 225개 패키지, 런타임 의존성 208개 확인 | 보관된 전체 픽셀 후보 |
| GA 기반 r6 시험 오버레이 | 서명 확인, 인덱스 232개 항목 중 설치된 221개 모두 일치 | 현재 VM의 실제 기준 |

**현재 VM과 전체 픽셀 저장소를 같은 기반으로 취급하면 안 된다.**
예를 들어 VM의 `ki2ctl`은 `0.1.0-37`, 전체 픽셀 저장소는 `0.1.0-22`다.
커널·base-files·OpenSSH 등을 포함한 14개 항목에 버전 차이 또는 공급 항목 차이가 있다.
이는 이번 점검으로 생긴 변경이 아니다. 설치된 221개 패키지는 직전 r6 검증 기록과 모두 같다.

현재 VM용 오버레이 인덱스 SHA-256:
`269b2f1683b781ea3d00f26d3b4a3466e67150a570140920824d1f92346c7f71`.

오버레이는 관리자·세션 패키지 **2개만 포함하는 시험용 공급본**이며 `not_for_iso=true`다.
232개 패키지 파일이 모두 있다는 뜻이 아니다. 다음 개발은 GA 기반을 유지하고, 구버전 전체
후보를 덮어씌워 버전을 내리지 않는다. 새 ISO 공급본은 GA 패키지 전체 확보·정합성 검증 후 별도로 구성해야 한다.

증거: `dependency-integrity.json`, `runtime-audit.json`.

## 3. 관리자 API 재사용 점검

현재 계약은 HTTP 서비스가 아닌 **로컬 JSON CLI**다. 일반 사용자 UID 1000에서 조회·계획만 실행했다.
관리자는 `0.1.0-7`, KI2는 `0.1.0-37`이다.

| 기능 | 이번 확인 | 새 운영 화면에서의 판단 |
| --- | --- | --- |
| snapshot | `ok=true`, `schema=kiki-admin-v1`, 경고 없음, 설치 221개·실패 서비스 0개 | OS·호스트·디스크·패키지 요약 재사용 |
| diagnose | 정상 JSON 응답, 경고 없음 | 진단 재사용 |
| 사용자 로그 | 정상 조회, 접근 제한 안내 포함 | 접근 범위와 notice를 함께 표시 |
| 서비스 로그 | 조회 성공 응답이지만 일반 사용자에게는 시스템 로그가 제한됨 | 빈 로그를 문제 없음으로 해석하지 않음 |
| 시스템 로그 계획 | 지정 서비스의 인증 조회 계획 생성 성공 | 기존 검토·인증 경로 재사용 |
| 실패하지 않은 서비스 재시작 계획 | 종료 코드 1, `ok=false`로 거부 | 실패 서비스만 복구하는 현재 범위 유지 |
| apply·실제 재시작 | 이번에는 실행하지 않음 | 읽기 전용 0단계와 후속 권한 작업 검증을 구분 |

서비스 로그의 실제 예에서는 `-- No entries --`와 함께 시스템 로그 접근 제한 notice가 반환됐다.
기존 관리자도 이 notice를 표시한다. 새 UI에서도 이를 유지하며, 필요한 경우 시스템 로그 인증
조회로 이어지게 한다. 로그를 보기 위해 사용자 그룹이나 Polkit 권한을 변경하지 않았다.

Polkit 정책은 고정 helper 경로에 대해 활성 세션 `auth_admin`, 비활성·기타 세션 `no`를 유지한다.
이번에 정책 파일·helper·설치 파일의 SHA·권한을 확인했으며 암호 입력 창을 재실행하지 않았다.
기존 관리자와 세션의 일반 파일 총 29개가 패키지 명세와 일치했다.

추가할 조회 기능은 CPU·메모리 샘플과 현재 로드된 서비스 목록·상태다.
기존 snapshot은 KI2 패키지 목록까지 계산하므로, 이를 고빈도 지표 갱신에 그대로 사용하지 않는다.
기존 로그·진단 응답 전체가 snapshot과 같은 schema 필드를 가진다고 가정하지 않고 명령별 응답을 처리한다.

## 4. Console과 GTK 런타임

| 구성 | 설치 버전 |
| --- | --- |
| GNOME Console | 50.0-1 |
| GTK4 | 4.22.4-2 |
| Libadwaita | 1.9.3-2 |
| VTE GTK4 | 0.84.1-1 |

Console·관리자·GIO의 동적 라이브러리 검사에서 `not found`가 없었다.
Console은 GTK4·Libadwaita·GTK4용 VTE·libgtop 등 기존 공용 라이브러리에 연결되어 있다.
Console 실행 파일과 GNOME Shell·세션·Nautilus·설정의 점검 대상 파일 7개도 서명된 패키지
명세와 SHA·권한이 일치한다. 일반 GNOME의 세션 파일 3개와 기본 사용자 dconf DB도 이전 SHA와 같다.

- 데스크톱 ID `org.gnome.Console.desktop`, `Exec=kgx`, `DBusActivatable=true` 확인.
- 사용자 D-Bus에서 `org.gnome.Console` 활성화 이름 등록 확인.
- 실제 도움말에서 명령·인수 실행, 작업 디렉터리 옵션 확인.
- 도움말의 `--wait`는 TODO 표시가 있으므로 관리 작업 성공 판정에 의존하지 않는다.
- 이번에는 도움말·로더·등록 상태만 확인했으며 새 터미널 창은 열지 않았다.

게스트에는 `pkg-config`가 없었다. 런타임 실행의 누락 라이브러리는 아니며,
설치 버전은 패키지 DB와 Console 도움말로 확인했다. 신규 앱 컴파일 도구와 헤더는
빌드 서버/SDK에서 준비하는 별도 작업으로 둔다. 게스트에 개발 도구를 설치하지 않았다.

## 5. 브라우저와 incident-ai

| 항목 | 결과 |
| --- | --- |
| 브라우저 데스크톱 등록 | 없음 |
| HTTP·HTTPS 기본 앱 | 모두 없음 |
| 조사한 두 후보 저장소의 Firefox/Epiphany/Chromium/WebKit 공급 항목 | 없음 |
| 후보 VM → incident-ai HTTPS | 기본 CA 인증서 검증을 켠 HEAD 요청으로 HTTP 200 |
| CA 저장소 | 해당 Python HTTPS 문맥에서 CA 147개 로드 |
| 실제 브라우저 로그인·화면·파일 전달 | 미검증 |

확인한 주소는 `https://incident-ai.lab.terminal-lab.kr/`이다. 요청에 로그·계정·토큰을 전송하지 않았다.
이번 결과는 일반 HTTPS 접근이 된다는 뜻이며 브라우저 로그인·JavaScript·SSO·API 연동 통과를 뜻하지 않는다.

기존 `kiki-ops-link`는 설정된 HTTPS 주소를 여는 기능이며 로그 전달 기능은 없다.
현재 막히는 지점은 브라우저 공급과 기본 앱 등록이다. 대상 ABI에 맞는 브라우저 패키지를
선정·공급하고 HTTPS 기본 앱 등록 및 실제 로그인 검증을 별도 후보에서 진행해야 한다.
서비스·로그 전달은 incident-ai 계약 확인 후 사용자 검토를 거치는 후속 기능으로 둔다.

## 6. 1단계 진입 조건과 순서

1. **실제 기반 고정:** GA 오버레이와 설치된 KI2 37을 기준으로 삼고 새 패키지 공급 경로를 정한다.
   기존 저장소·일반 GNOME 프로필·운영 세션을 이번에 교체하지 않았다.
2. **독립 GTK 골격:** 자체 앱 ID·픽셀 자산·설정 저장소를 가진 화면부터 구성한다.
   CPU·메모리·서비스 상태의 경량 조회 계약을 먼저 정한다.
3. **로그·터미널 연결:** 현재 접근 범위 표시, 시스템 로그 계획·인증 분리, Console 실행을 구현한다.
4. **incident-ai 선행 의존성:** 브라우저 패키지·기본 HTTPS 앱·실제 로그인 검증을 완료한다.
   UI 골격과 로컬 관리 기능은 이 작업과 분리해 진행할 수 있다.
5. **자동 실행 분리:** 기존 `kiki-ops-desktop.service`는 `gnome-session@kiki-ops.target`에 종속된다.
   새 앱은 전용 설정과 표준 자동 실행을 사용하고, 두 경로의 중복 실행을 방지한다.

실제 서비스 변경·브라우저 설치·자동 실행 변경·새 앱 구현·빌드·ISO 생성은 이번에 하지 않았다.
0단계 점검 완료를 독립 데스크톱 구현이나 Stage 3 최종 배포 완료로 표시하지 않는다.

기계 판독 요약: `artifacts/kiki-operations/20261106-stage0/stage0-summary.json`.
