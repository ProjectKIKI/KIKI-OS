# 빌드 웹의 한글 UI·버전 보관·ISO 작업

서버의 기존 작업본과 설치기 패키지를 보존하면서, 후보 환경에 별도의 버전 보관소와 ISO 작업자를 구성했다. 기존 컴파일 컨테이너를 재시작하지 않고 배포할 수 있다.

## 접속과 구성

- SSH 터널로 `http://127.0.0.1:18090`에 접속한다. 기존 관리자 계정과 로그인 세션을 유지한다.
- 인증 게이트웨이: 서버 `127.0.0.1:8092`.
- 후보 패키지 컴파일러: 서버 `127.0.0.1:8091`.
- 버전 보관·ISO 작업자: 서버 `127.0.0.1:8094`.
- 원래 빌드 서비스 `127.0.0.1:8090`과 `/home/lab/kiki-os`는 유지한다.
- 신규 서비스는 rootless Podman과 사용자 systemd 서비스로 실행한다. 외부 공개 포트와 별도 공개 계정을 만들지 않는다.

후보 기준 경로는 `/build-kikios/kiki-build/candidates/mesa-native-20261023`이다. `release-code`는 실행 코드, `release-store`는 신규 보관 파일과 ISO 작업 결과다. 컴파일용 SDK와 원본 패키지는 ISO 작업자에게 쓰기 권한을 주지 않는다.

## 웹에서 사용하는 순서

1. **개별 패키지 빌드**에서 검토된 빌드 명세를 선택하고 빌드한다. 로그·상태·설명은 한글이며, 패키지 식별자·명령·컴파일러 출력은 원문을 보존한다.
2. **소스·바이너리 버전**에서 패키지 이름이나 버전을 검색한다. KI2·원본 소스·파일 명세를 내려받고 SHA·의존성·출처·검증 범위를 확인한다.
3. **완료 패키지 동기화·SHA 확인**은 비동기 작업으로 실행한다. 완료된 일반 패키지는 파일 명세 검사 후 등록하며, 런타임 검증 여부를 별도로 표시한다.
4. **새 스냅샷 보관**으로 기존 버전을 새 이름에 고정한다. 같은 이름의 스냅샷은 덮어쓰지 않는다. 패키지 SHA와 소스 SHA 연결, 인덱스·후보 서명·공개키를 함께 기록한다.
5. **ISO 생성**에서 고정 스냅샷과 GNOME 50 또는 최소 systemd 구성을 선택한다. 작업별 로그와 완료 후 ISO·SHA-256·검증 명세를 제공한다.

## 보관 및 검증 규칙

- 파일은 SHA-256을 키로 하는 별도 보관 객체에 복사한다. 원본 파일을 이동하거나 원본과 하드링크하지 않는다.
- 복사 전후 SHA를 검사하며, 기존 보관 객체가 손상되면 덮어쓰지 않고 오류를 표시한다.
- 개별 패키지의 동일 버전·동일 릴리스라도 내용 SHA가 다르면 별도 기록을 유지한다.
- 공식 HTTPS URL과 고정 SHA가 있는 소스만 확보 작업을 제공한다. SHA가 일치한 뒤에 다운로드에 표시한다. 소스 서명 검증은 SHA 검증과 구분한다.
- 소스 URL이나 고정 SHA를 확인할 수 없는 항목은 미등록으로 표시한다. 모든 바이너리의 소스 확보가 끝났다는 의미는 아니다.
- LLVM·Mesa 신규 쌍은 재빌드와 독립 루트의 렌더링 검증 결과가 모두 통과해야 자동으로 새 후보 스냅샷에 반영한다. 기존 LLVM·Mesa 버전은 남긴다.
- ISO 입력 KI2 SHA, 인덱스와 메타데이터 SHA, 후보 Ed25519 서명, 실행 의존성, 루트 파일 명세, ISO SHA 및 BIOS·UEFI 부팅 카탈로그를 검사한다.
- 현재 설치기 KI2의 파일명과 고정 SHA를 확인한 경우에만 과거 표시 이름을 허용한다. 설치기 실행 파일과 KI2 내용은 변경하지 않는다.
- 큰 임시 파일은 `release-store/tmp`에 생성한다. 컨테이너의 작은 `/tmp` tmpfs를 대용량 설치기 추출에 사용하지 않는다.

## LLVM 재개 시 발견한 호스트 도구 경로

LLVM 21.1.8 대상 라이브러리 빌드의 마지막 단계에서 자동 `NATIVE/llvm-config` 하위 빌드가 대상용 CFLAGS/LDFLAGS를 상속했다. 그 결과 호스트에서 실행할 보조 프로그램이 대상 glibc를 요구했다.

후보 CMake 캐시에 `LLVM_NATIVE_TOOL_DIR=/usr/bin`, `LLVM_CONFIG_PATH=/usr/bin/llvm-config`를 명시했다. 컨테이너의 검증된 호스트 LLVM 21.1.8 도구를 선택하며, 대상 라이브러리는 계속 KIKI sysroot로 빌드한다. 기존 오브젝트·소스·고정 빌드 드라이버는 유지했다. 수정 옵션과 고정 드라이버 SHA는 서버의 `validation/host-tool-recovery.json`에 별도로 기록했다. 새 후보를 준비할 때는 처음부터 두 옵션을 지정해야 한다.

## 검증 범위

LLVM C API의 IR 검증·JIT 결과 확인과 Mesa의 surfaceless 소프트웨어 렌더링은 빌드 컨테이너에서 검사한다. 이 검사는 Hyper-V의 새 ISO 설치·GDM/Wayland 로그인·하드웨어 GPU 검사를 대신하지 않는다. ISO 검증 명세에도 실제 설치·로그인·Secure Boot 서명 여부를 별도로 표시한다.

스냅샷은 후보 저장소다. 최종 배포 저장소 승격이나 기존 설치기 교체를 자동으로 수행하지 않는다. 원본과 과거 작업 이력의 삭제 기능은 제공하지 않는다.
