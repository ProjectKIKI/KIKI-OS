# 빌드 웹 사용자 관리

관리자로 로그인한 뒤 상단의 **사용자 관리**(`/users`)를 엽니다.
기존 관리자의 아이디·비밀번호와 인증 저장소를 유지하면서 계정별 권한을 추가합니다.
이 기능은 빌드 웹 계정을 관리하며, Linux/SSH 계정을 생성하지 않습니다.

## 권한

| 권한 | 사용 범위 |
|---|---|
| 관리자 | 사용자 추가·권한·활성 상태·임시 비밀번호·세션 관리, 전체 빌드 운영 |
| 운영자 | 패키지·소스·바이너리·릴리즈·ISO 작업, 상태·로그 조회 및 다운로드 |
| 조회자 | 상태·로그 조회 및 산출물 다운로드 |

모든 권한은 인증 서비스에서 검사합니다. 조회자의 작업 폼은 비활성으로 표시하며,
직접 HTTP 요청을 보내도 빌드 및 릴리즈 작업자로 전달되지 않습니다.
운영자와 조회자는 사용자 목록 및 계정 관리에 접근할 수 없습니다.
모든 사용자는 **내 계정**(`/account`)에서 본인 비밀번호를 변경할 수 있습니다.

## 운영 흐름

1. **사용자 추가**에서 아이디와 권한을 선택합니다. 기본 권한은 조회자입니다.
2. 생성 직후 한 번 표시되는 임시 비밀번호를 사용자에게 안전하게 전달합니다.
3. 사용자는 첫 로그인 후 본인 비밀번호로 변경하고 다시 로그인합니다.
4. 관리자는 계정별 관리 화면에서 권한 변경, 비활성화, 임시 비밀번호 재발급,
   전체 세션 종료를 수행합니다. 영구 삭제 대신 비활성화를 사용합니다.

아이디는 영문·숫자·점·밑줄·하이픈으로 1~64자이며 `.`·`..`·`new`는 예약되어 있습니다.
대소문자만 다른 중복 아이디를 새로 만들 수 없으며 로그인은 등록한 표기를 사용합니다.
비밀번호는 15~1024자, 기존 방식인 PBKDF2-HMAC-SHA256 600,000회로 저장합니다.
임시 비밀번호 원문을 DB·감사 기록·URL에 저장하지 않습니다.
임시 비밀번호 화면은 `no-store`로 응답합니다. 다시 열어 조회할 수 없으며 분실 시 재발급합니다.

권한·활성 상태 변경과 비밀번호 재발급은 대상 계정의 세션을 종료합니다.
본인 비밀번호 변경은 본인의 모든 세션을 종료하며, 다른 사용자의 세션은 유지합니다.
실행 중인 빌드와 산출물은 계정 변경으로 삭제하거나 중단하지 않습니다.
본인의 관리자 권한 하향·비활성화·관리자 화면을 통한 비밀번호 초기화는 차단합니다.
마지막으로 사용 가능한 관리자 보호와 변경 번호 검사는 SQLite 쓰기 트랜잭션에서 수행합니다.
새 비밀번호 설정 전 계정은 운영 콘솔과 사용자 관리 작업을 사용할 수 없습니다.

최근 30건의 계정 변경 이력을 목록에서 확인할 수 있습니다.
인증 DB의 `account_events`에는 작업자·대상·시각·작업 종류와 권한/상태만 기록합니다.
기존 로그인 감사 파일도 유지합니다. 활동 시각은 UTC로 표시합니다.

## 배포 및 보존

- `ki2ci_auth.py`, `ki2users.py`, `ki2users_views.py`를 인증 이미지에 포함합니다.
- 인증 DB는 기존 `auth/state` 볼륨 한 곳을 계속 사용합니다. 비밀번호 DB를 복사하지 않습니다.
- 시작 시 기존 `users`에 권한·활성·초기 변경 여부·변경 번호·시각 열을 추가합니다.
  기존 계정은 활성 관리자로 이관하고 기존 salt·비밀번호 해시·세션 토큰은 유지합니다.
  기존 계정의 과거 등록 시각은 추정하지 않고 ‘기존 계정’으로 표시합니다.
- 인증 컨테이너만 교체합니다. 컴파일러·릴리즈 작업자, 외부 연결 포트는 유지합니다.
- 설정 파일과 이전 이미지를 보존합니다. 계정이 여러 개 만들어진 후에는 권한을 모르는
  이전 단일 관리자 이미지로 되돌리지 않습니다. 수정 이미지도 동일한 계정별 권한 검사를
  유지해야 합니다. DB 마이그레이션의 열과 계정 변경 이력은 제거하지 않습니다.
- SSH 복구용 `reset-password --username <아이디>` 명령은 해당 계정의 비밀번호와 세션만
  변경합니다. 관리자 서버 접근 권한이 있는 운영자의 복구 경로입니다.

## 검증

`tools/test_ki2ci_auth.py`는 기존 로그인·CSRF·출처·스트리밍 검증에 더해 구형 DB 이관,
계정 추가, 임시 비밀번호, 역할별 직접 요청 차단, 대상 세션 종료, 잘못된 현재 비밀번호,
자기 계정 잠금 방지, 동시 관리자 권한 하향, 변경 번호 충돌을 확인합니다.
릴리즈·버전·ISO 테스트도 함께 실행해 기존 작업 연결을 점검합니다.
실제 서버에서는 기존 관리자 계정을 초기화하거나 테스트 사용자를 남기지 않고
목록·검색·등록 양식·계정 상세·내 계정 화면과 기존 릴리즈 화면 연결을 확인합니다.
