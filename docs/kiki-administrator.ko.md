# KIKI 관리자 구성과 검증

표준 GNOME 데스크톱과 기본 앱을 유지하면서 KIKI의 시스템·패키지·진단
관리를 별도 앱에 모았다. 소스와 사용법은
[`cmd/kiki-admin/README.ko.md`](../cmd/kiki-admin/README.ko.md)에 있다.

## 배포 후보

- 네이티브 앱: `kiki-admin 0.1.0-3`, GTK4 / Libadwaita.
- 공통 패키지 CLI: `ki2ctl 0.1.0-22`.
- 별도 서명 후보: `dist/ki2/kiki-admin-20261028-r4`.
- 전체 저장소 224개, GNOME 프로필 런타임 207개.
- 인덱스 SHA-256: `943f7b5cb3ac05ef3e5099f47fbd0de3d112b7f5a032579b0e639d74d2383849`.
- 공개키 SHA-256: `b6aaadb5491676d154efc62c0bf20a2f6b1026a741d92698d99c75f18390f4f4`.

GNOME 그룹의 기본 패키지에 관리자를 추가하고 프로필을 새 후보에 고정했다.
기존 GNOME 기본 앱·기존 ISO·이전 패키지 후보는 보존했다. 후보 내 동일한
불변 패키지 바이트는 하드링크로 재사용하므로 별도 복사보다 공간을 적게 쓴다.

## 실제 VM 검증

기존 전용 시험 VM `kiki-gnome-apps-r3-20261028`의 디스크 설치 환경에서
서명된 KI2로 앱과 CLI를 설치했다. 새 ISO 설치 시험과는 구분한다.
실제 GNOME Wayland 세션에서 아래 항목을 확인했다.

- 시스템 개요·패키지·저장소·진단 화면, 검색, 변경 검토 창을 렌더링하고 캡처.
- 작은 창과 작업 중 창 닫기 방지.
- 저장소 메타데이터의 서명 검증과 목록 동기화.
- 일반 사용자 변경 거부와 검토 이후 상태가 달라진 요청 거부.
- 이미 구성된 GNOME 그룹의 소유권 등록 및 갱신 계획.
- 전용 일회성 서비스를 실패시켜 상태에 표시하고, 검토한 재시작으로 복구.
- 현재 사용자 로그와 관리자 권한으로 읽는 실제 시스템 서비스 로그.
- 실제 루트 파일시스템 여유 공간, 실패 서비스 0개, 정보 조회 오류 0개.

관리자 권한 작업은 고정 helper를 테스트 계정의 기존 sudo 권한으로 실행해
검증했다. Polkit 정책의 활성 세션 `auth_admin`, 비활성·원격 세션 `no`와
정확한 helper 실행 경로를 검사했다. 사용자 인증 다이얼로그의 암호 입력은
자동화하지 않았다. 자동 로그인을 활성화하거나 암호를 바꾸지 않았다.

증거는 `artifacts/kiki-admin-test/acceptance.json`, `ui-test.log`와 PNG들에 있다.
컨테이너·Kubernetes·AI 관리는 후속 영역으로 표시하며 구현 완료로 취급하지 않는다.

## 검증 중 수정한 KI2 문제

설치기로 만든 패키지 DB는 공용 디렉터리도 파일 소유권에 기록했다. 이 상태에서
CLI가 `/usr`·`/etc` 등의 정상 공유 디렉터리를 다른 패키지의 파일 충돌로 처리해
추가 설치를 막았다. 일반 디렉터리 공유를 허용하고 새 rootfs DB에서는 디렉터리와
생성형 Info 색인을 소유 파일 목록에서 제외했다. 일반 파일·심볼릭 링크 충돌은
계속 차단한다. 기존 DB의 디렉터리 기록도 호환 처리한다.

기존 시험 VM의 구버전 CLI는 자체 업데이트도 이 검사에 걸리므로, 원본 CLI를
백업하고 해시 검증한 새 패키지의 CLI만 먼저 복구한 뒤 정상 KI2 트랜잭션으로
두 패키지를 설치했다. 이후 그룹 등록과 서비스 복구는 실제 새 CLI·helper를 썼다.
