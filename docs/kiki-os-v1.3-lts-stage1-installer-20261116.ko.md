우선 평가**, 지원 기준은 **GA부터 24개월**로 승인됐다. 이번 단계에서 커널을
교체하거나 지원 종료일을 확정하지 않는다. incident-ai 자동 연동은 보류한다.

## 카탈로그 SHA 차이 처리

기존 release 28 런타임은 Windows 작업본의 CRLF 카탈로그를 잠갔다. Git 아카이브는
LF이므로 JSON 내용이 같아도 SHA가 다르다. 재패키징이 이를 실제로 거부했다.

- 기존 바이트 SHA: `fa31119f8e4cf1edba351bb1c03be9ca28403a183a41eb8bfd22d904c9716222`.
- Git 아카이브 LF SHA: `ce60aa62dac385b8040a2211b8cec605f8f31cf817612d8febf884efab72785f`.

이번 후보는 JSON 동일성을 확인한 후 기존 바이트를 그대로 고정한다. SHA 비교를
생략하거나 런타임 명세만 임의 변경하지 않는다. 이후 Git 소스로 전체 런타임·미디어를
재생성할 때 LF로 통일하고 새 카탈로그 SHA를 함께 잠근다. 소스 패치만 Git에 적용하면
줄바꿈이 정규화될 수 있으므로 이번 KI2 재현에는 `catalog-pin.json`과 원본 바이트가 필요하다.

## 검증 방법과 한계

기존 서버 이미지를 기반으로 새 rootless 검증 이미지를 만들었다. GTK 개발 파일·Xvfb는
새 이미지에만 설치했고 서버의 패키지·서비스 설정을 바꾸지 않았다. 시험 실행은 네트워크를
차단하고 후보 소스는 읽기 전용, 결과 디렉터리만 쓰기 가능하게 마운트했다.

- 실제 Go 계획 생성기 단위 검사.
- 빌드 기본값·브랜드·카탈로그·KI2 재패키징 계약 8개.
- 실제 GTK 창·네트워크·디스크 탐색 3개. 한국어/영어, 1024×768·800×600 렌더링.
- Stage-1 오류 전파·미디어 검증·요청 파서·진행 상태 관련 44개.
- C 컴파일: `-Wall -Wextra -Werror`, x86-64-v2 목표.

GTK는 실제 Go 실행 파일을 호출한다. 서버 기본/GNOME 계획, 재동의, 중복 계획 차단,
이벤트 루프 응답, 취소·시간 초과·계획 실패, 요청 덮어쓰기 거부, 진행·실패·완료·명시적
재부팅 요청을 시험했다. 설치·재부팅 요청의 목적지는 임시 fixture이며 실제 디스크에 쓰지 않는다.

Xvfb에서 DRI3 가속 관련 EGL 경고와 컨테이너 기본 shader cache 경로 권한 경고가
기록됐다. 화면은 Cairo로 렌더링됐고 검사는 통과했다. 이 결과는 Wayland/DRM,
Hyper-V GPU 또는 실제 로그인 성공의 증거로 사용하지 않는다.

## 1단계 종료 판정에서 남은 항목

이번 결과는 **후보 구현·격리 시험**이다. 공식 ISO 전환과 1단계 전체 인수 완료는
아래 실증 이후 판정한다.

1. 통합 공급 기준선에서 LF 카탈로그와 전체 런타임을 재생성하고 새 서명·인덱스 고정.
2. 새 후보 ISO의 GUI → TUI → CLI 폴백과 설치 시작 후 중복 실행 차단 실제 시험.
3. 별도 빈 디스크에 서버/GNOME 설치, 오프라인 재부팅, 계정·sudo·GDM/Wayland·GNOME 앱 확인.
4. GUI/TUI/CLI/무인 설치의 대표 입력과 실제 설치 결과 비교. 시험용 암호와 운영 자격증명 경로 분리.
5. v2 기능으로 제한한 VM의 번들 전체 실행·부팅. 6.12 커널 정확한 버전·SHA·설정 평가.
6. 정식 인수 해상도·배율·라이트/다크·키보드 탐색과 실패 복구 시나리오 검증.

## incident-ai KI2 권장 범위

선택형 패키지는 유용하다. 우선 **접속 URL·바로가기·실행/업데이트 서비스 정의**를
담는 얇은 패키지로 두고 OS 기본 설치와 분리하는 안을 권장한다. 서버 본체는 별도
버전의 OCI 이미지 digest로 고정하고, 모델·데이터·비밀값·인증서는 패키지에 넣지 않는다.
컨테이너 서비스를 택할 경우 [Podman Quadlet 공식 문서](https://docs.podman.io/en/latest/markdown/podman-systemd.unit.5.html)의
systemd 연동 방식을 평가할 수 있다.

실제 incident-ai 서버 전체 소스·배포 계약을 이번에 감사한 것은 아니다. 향후 KI2의
서비스 소유권·데이터 마이그레이션·오프라인 이미지 공급·업데이트/복구 정책을 먼저 정한다.
이번에는 incident-ai 패키지 생성·수신기 배포·자동 전송을 진행하지 않는다.
