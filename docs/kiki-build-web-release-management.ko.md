# 릴리즈별 패키지·ISO 관리

운영 화면은 [릴리즈 관리](https://cloud-7-3b778824-09936d.lab.terminal-lab.kr/releases)다. 기존 계정으로 접속하며 릴리즈, CPU 구성, 패키지 스냅샷, ISO 작업을 연결해 관리한다.

## 구성과 사용하는 순서

1. **릴리즈 관리**에서 기존 OS 버전과 과거 ISO 묶음을 확인한다. 상세 화면은 요약·패키지·ISO·변경 비교·설정으로 나뉜다.
2. **새 릴리즈 등록**에서 기준 스냅샷을 불러온다. 패키지 버전 교체·추가·제외를 선택하고 릴리즈 이름, 제목, 메모와 기본 운영 구성을 입력한다. 선택한 값만 변경 목록으로 전송한다. 화면에서 패키지를 검색해 숨겨도 선택한 변경은 유지한다.
3. 등록 작업은 패키지 SHA, 실행 의존성, 필수 운영 패키지, CPU 등급과 후보 서명을 확인한다. 패키지가 바뀌면 별도 스냅샷을 만들고, 바뀌지 않으면 검증한 기존 스냅샷을 참조한다.
4. 등록한 릴리즈의 **패키지**에서 포함 버전·SHA·의존성을 검색하고 KI2·소스·파일 명세를 내려받는다. 소스 확보 여부와 바이너리 런타임 검증 범위는 따로 표시한다.
5. **ISO**에서 해당 릴리즈·CPU의 고정 구성으로 ISO를 요청한다. 동일 버전의 여러 ISO 작업과 GNOME 50/최소 systemd 변형을 보존한다. ISO·SHA·검증 명세와 실제 설치·GDM·Secure Boot 상태를 함께 보여준다.
6. **변경 비교**에서 같은 CPU 대상의 다른 릴리즈를 선택한다. 패키지 추가·제외·교체를 SHA 기준으로 비교하므로 표시 버전이 같아도 내용이 다르면 교체로 나타난다.

## 보존과 변경 규칙

- 릴리즈의 기존 CPU 구성은 교체하지 않는다. 패키지를 바꾸려면 다음 릴리즈를 새 이름으로 등록한다.
- 기존 OS 버전은 바로 관리 화면에서 읽는다. 릴리즈 이름 없이 생성한 과거 ISO는 원래 스냅샷을 기준으로 **기존 보관 · 관리 미등록** 상태로 보여준다. 조회만으로 파일을 수정하지 않는다.
- 과거 자료는 설정의 **관리 등록**으로 SHA·의존성·서명을 재확인할 수 있다. 같은 과거 릴리즈 이름에 다른 패키지를 연결하는 요청은 거부한다.
- ISO 입력 핀은 기존 `release-versions/<버전>/manifest.json`을 계속 사용한다. 제목·메모·관리 상태·변경 이력은 별도의 `release-management/<버전>/record.json`에 저장한다.
- 모든 파일과 이전 ISO는 유지한다. 보관 해제 시 기존 다운로드와 입력 핀을 그대로 사용한다. 삭제·덮어쓰기나 외부 공식 배포 기능은 추가하지 않는다.

## 관리 상태

| 상태 | 가능한 동작 |
|---|---|
| 후보 | 기존 핀으로 ISO 생성, 새 CPU 구성 등록, 구성 잠금, 보관 |
| 구성 잠금 | 기존 핀으로 ISO 생성, 잠금 해제, 보관. 새 CPU 구성 등록은 잠금 해제 후 가능 |
| 보관됨 | 기존 패키지·ISO 다운로드, 메모 수정, 보관 해제. 새 ISO 생성은 중지 |
| 기존 보관 · 관리 미등록 | 과거 패키지·ISO 조회와 비교, 원래 구성의 관리 등록 |

제목·메모 변경은 입력 패키지를 바꾸지 않는다. 관리 상태 변경은 진행 중인 릴리즈·ISO 작업이 끝난 뒤 가능하다. 폼의 수정 번호가 현재 번호와 다르면 새로고침을 요구하여 다른 화면의 변경을 덮어쓰지 않는다. 변경 시각·동작·이전·이후 상태를 기록한다.

구성 잠금은 공식 배포 승인이나 실제 설치·로그인 검증을 의미하지 않는다. x86-64-v3/v4는 해당 CPU 대상 패키지와 런타임 검증을 확보한 뒤 등록한다. 기존 바이너리의 이름만 바꾸거나 미검증 구성을 v3/v4로 표시하지 않는다.

## 운영 배포

후보 코드 경로는 `/build-kikios/kiki-build/candidates/mesa-native-20261023/release-management-20261025-r1/release-code-r5`이며 실행 데이터는 기존 `release-store`를 재사용한다. 인증 이미지는 `localhost/kiki-build-auth:release-management-20261025-r3`, 소스 잠금은 같은 후보 디렉터리의 `stage-r5/source-lock.json`이다.

인증 서비스는 새 `/releases` 경로를 기존 릴리즈 작업자로 전달한다. 인증·CSRF·Origin·세션 제한을 유지한다. 릴리즈의 한글 메모와 패키지 변경 목록을 위해 해당 폼 경로만 최대 128KiB를 허용하고, 필드 수 제한과 기존 로그인 폼 한도는 유지한다.

배포 전 서비스 설정을 후보의 `before`에 보관한다. 기존 설치기·원본 패키지·이전 코드와 인증 상태 볼륨은 유지한다. 인증 DB 사본은 만들지 않는다. 컴파일러와 포트·보안그룹 설정을 바꾸지 않고 인증·릴리즈 웹 서비스만 교체한다. 되돌릴 때는 작업이 없는지 확인한 후 이전 코드 경로와 인증 이미지 설정을 복원한다. 새 릴리즈 파일은 지우지 않는다.
