# KIKI OS v1.3 LTS 최종 개발·출시 계획

작성일: 2026-11-16 (한국 시간)

0단계 조사 결과: [보존·설치기·공급 기준·지원 범위 점검](kiki-os-v1.3-lts-stage0-review-20261116.ko.md).
읽기 전용 점검은 완료했으며 LTS 담당·기간 승인 등 전체 종료 조건은 해당 기록을 따른다.

**상태: 사용자가 C/GTK4 주력·x86-64-v2 최소 CPU 목표·6.12 LTS 우선 평가·24개월 지원 기준을 승인했다. 1단계는 별도 후보에서 진행하며 운영 배포는 하지 않는다.**

진행 기록: [1단계 설치기 단일화 후보](kiki-os-v1.3-lts-stage1-installer-20261116.ko.md).
아래 비교·권고와 과거 검증 설명은 계획 작성 시점의 근거다. 실제 완료 여부는 단계별 진행 기록을 따른다.

사용자가 확정한 버전 대상은 **KIKI OS 전체**다. 설치기, 기본 OS, 패키지,
GNOME 운영 환경, KIKI 운영 화면, 설치 ISO와 업데이트·복구를 함께 다룬다.
아래의 구현 선택과 지원 정책은 이 계획의 권장안이며, 현재 코드에 적용됐거나
LTS 지원이 개시됐다는 뜻이 아니다. 정식 출시일과 지원 종료일은 아직 미정이다.

## 1. 목표와 버전 원칙

v1.3은 기존 기능을 일관된 설치·운영·업데이트·복구 경로로 완성하는 안정화 릴리즈다.
“최종 LTS”는 이 기능 집합을 동결한다는 의미이며, 출시 후 보안·치명적 오류 수정을
중단한다는 의미가 아니다. 필수 기능이 검증되지 않으면 날짜나 버전명만으로 출시하지 않는다.

| 구분 | 계획 |
|---|---|
| 제품 버전 | KIKI OS 1.3.0 LTS |
| 유지보수 버전 | 1.3.1, 1.3.2 등. 버전마다 별도 불변 패키지 스냅샷과 ISO 사용 |
| 후보 식별 예 | `os-v1.3.0-rc1`, `os-v1.3.0-rc2` |
| 정식 태그 예 | `os-v1.3.0` |
| 빌드 도구 | KIKI Build의 독립 버전을 유지하고 실제 사용한 커밋·이미지 digest·도구 버전을 OS 명세에 기록 |
| 패키지 버전 | 업스트림 버전과 KI2 release를 유지. 모든 패키지를 1.3.0으로 일괄 변경하지 않음 |
| 기존 개발 단계 | Stage1/2/3는 개발 단계 기록으로 보존. OS 1.3과 같은 버전 체계로 취급하지 않음 |

태그·채널·파일명은 제안이다. 이 문서 작성으로 생성하거나 변경하지 않는다.

## 2. 검토 근거와 현재 차이

현재 소스와 기존 검증 기록을 바탕으로 한 출시 준비 검토다. 이번에 새 VM 설치,
전체 SHA 재계산, 보안 전수 감사 또는 서버 상태 재검사를 실행한 것은 아니다.
이전 통과 기록은 해당 ISO·패키지·VM에만 적용하며, v1.3의 새 통과 증거로 재사용하지 않는다.

| 영역 | 확인한 기반 | 남은 차이 |
|---|---|---|
| 설치기 | C/GTK4, Go/gotk4, Go 계획 생성기/TUI, Stage-1 실행기 | C와 Go GUI의 기능·기본 빌드 경로·문서가 다름 |
| 실제 설치 | GNOME 후보 및 Build 1.0.0 관련 Hyper-V 신규 설치·부팅 기록 | 한 v1.3 ISO에서 현재 기능 전체를 검증한 기록은 없음 |
| 운영 환경 | GNOME/GDM/Wayland, 네이티브 Mesa·LLVM, 기존 GNOME 앱 | 보존 GNOME 저장소·GA VM·운영 앱 후보의 버전과 공급 범위가 다름 |
| 운영 앱 | 상태·서비스·로그·Console·수동 incident-ai 연결 | 얇은 후보 오버레이는 전체 ISO 공급 저장소가 아님 |
| 빌드 웹 | HTTPS Git 소스 동기화, 작업별 입력 고정, 릴리즈별 산출물 관리 | 최신 빌드 입력 동기화가 운영 웹 코드 교체나 새 OS 검증을 뜻하지 않음 |
| 복구 | 백업·후보 검증·안정 채널 승격 기반 | 부분 파일 보호와 빈 서버 전체 복원, 패키지 복구와 전체 OS 원자적 롤백을 구분해야 함 |

일반 GNOME 후보, 전체 픽셀 후보, GA 기반 시험 VM을 서로 같은 기준선으로 간주하지 않는다.
특히 `not_for_iso=true` 오버레이를 전체 패키지 공급본으로 승격하거나, 구버전 후보로
설치된 최신 KI2·커널·OpenSSH 등을 낮추지 않는다.

## 3. 정식 지원 범위

### 3.1 기본 범위

- 서버 기본 구성과 GNOME 운영 구성의 두 설치 선택을 제공한다. 공통 코어와 패키지
  버전은 공유하고, 최종 설치 집합과 ISO·스냅샷 식별은 구성별로 명확히 기록한다.
- x86_64, UEFI/GPT, 검증한 전체 디스크 자동 설치를 기본으로 한다.
- Hyper-V Generation 2와 QEMU/KVM UEFI를 우선 검증 플랫폼으로 한다.
- 오프라인 로컬 미디어 설치, 관리자 계정, root 직접 로그인 잠금, SSH,
  유선 DHCP·고정 주소·DNS, systemd·D-Bus·logind·Polkit를 지원한다.
- 서명된 KI2 패키지 설치·업데이트·상태 조회와 명시적 복구 절차를 제공한다.
- GNOME 운영 구성은 GDM/Wayland, Console·파일·설정·시스템 감시 등 선택한
  기존 GNOME 앱과 작은 KIKI 운영 화면을 유지한다. LightDM을 정식 로그인 경로로 되돌리지 않는다.
- 운영 화면은 실제 상태·실패 서비스·권한이 구분된 로그·터미널·기존 관리자 연결을 제공한다.
  상태 조회와 권한이 필요한 조치를 분리하고, 조치의 최종 결과를 다시 확인한다.
- incident-ai는 기존 HTTPS 연결과 사용자 검토·수동 전달까지만 포함한다.
  자동 채우기 수신기·자동 전송·AI 조치 자동 실행은 계속 보류한다.

### 3.2 출시 계약에서 별도 취급할 범위

| 항목 | v1.3 방침 |
|---|---|
| CPU 최소 기능 | “x86_64” 이름으로 초기 CPU 호환을 보증하지 않음. 실제 ISA·컴파일 옵션을 조사하고 최소 CPU 기능으로 제한한 VM에서 검증 후 명시 |
| x86-64-v3/v4 | 대상별 전체 패키지·런타임 증거가 없으면 비활성 유지. 이름만 바꾸어 공급하지 않음 |
| BIOS 설치·Secure Boot | 검증된 설치 대상 부트 체인을 별도로 확보하지 않으면 정식 지원에서 제외하고 ISO·문서에 표시 |
| GUI 수동 파티션·LUKS·LVM·RAID | 이번 기본 계약에서 제외. CLI의 별도 기능과 GUI 지원을 혼동하지 않음 |
| 원격 패키지로 신규 설치 | 로컬 설치와 동일한 검증·실패 복구 백엔드가 준비되지 않으면 계획 전용 또는 미지원으로 표시 |
| Wi-Fi·물리 GPU·특수 하드웨어 | 시험하지 않은 장치를 정식 지원으로 표시하지 않음. 물리 서버는 지정한 모델의 인수 시험 후 목록에 추가 |
| Kubernetes | 역할별 패키지·정책을 분리. init/join·재시도·CNI·재부팅 실제 증거가 없는 역할은 실험 범위로 표시하고 기본 LTS 보증에 포함하지 않음 |
| 독립 Server Shell | GNOME 포크·새 compositor·패널은 제외. 운영 앱의 독립 UI와 GNOME 유지 원칙을 따른다 |

제외된 항목은 이유와 사용자 영향이 승인된 경우에만 예외로 남긴다.

## 5. 설치기 단일화 계획

### 5.1 권장 선택

**v1.3 공식 GUI는 C/GTK4 경로를 기준으로 단일화하는 것을 권장한다.** 최근 GNOME
설치 후보가 사용한 경로이며, 미디어 가용성·프로필 선택 등 기존 기능을 연결하기 쉽다.
Go 계획 생성기/TUI와 Stage-1 실행기는 재사용하고 GUI 언어를 새로 바꾸지 않는다.

Go/gotk4 소스와 이전 산출물은 삭제하지 않는다. 이력·호환 시험 대상으로 보존하되
v1.3의 대체 기본값으로 자동 선택되지 않게 한다. 현재 그래픽 도구의 gotk 기본값과
일부 문서의 C 기본값 설명이 다르므로, 구현 전에 비교표와 선택 근거를 확정한다.
비교 중 치명적인 차이가 나오면 계획을 수정하고 다시 결정하며, 조용히 다른 GUI로 빌드하지 않는다.

### 5.2 완료 기준

- GUI 구현 선택이 공식 빌드 계획·패키지 레시피·재패키징·ISO 경로에 일관되게 반영된다.
- 런타임 명세에 GUI 구현·패키지 버전·실행 파일 SHA·소스 커밋·카탈로그 SHA를 기록한다.
- GUI/TUI/CLI/무인 설치의 대표 입력을 비교해 계획과 설치 결과가 일치한다.
- GUI 실패 → TUI → CLI 폴백을 설치 시작 전 상태에서 실제 시험한다.
- 설치 시작 이후에는 다른 설치 실행기가 동시에 동작하거나 파괴적 재시작하지 않는다.
- 암호는 인자·계획서·로그·ISO에 남지 않고 기존 요청·진행 상태 전달 경계를 유지한다.
- 자동 설치의 시험용 계정 경로와 운영용 자격증명 공급 경로를 구분한다.
- 원격·미러 선택은 실제 지원 여부를 화면에서 미리 설명한다. 마지막 설치 버튼에서 처음 거절하지 않는다.

## 6. 패키지·ISO 기준선 통합

1. 기존 설치기·원본 패키지·남은 ISO·GNOME 앱·후보 VM의 보존 목록과 SHA를 새 시점에 확인한다.
2. 설치된 GA 기반과 전체 공급 저장소를 패키지 이름·버전·release·SHA·파일 소유권 단위로 비교한다.
3. 누락 파일·의존성·서명·버전 역행을 해결한 독립 v1.3 공급본을 만든다.
4. 공통 GTK와 설치기 전용 런타임을 분리한다. 설치기 번들의 라이브러리를 GNOME의 공용 공급자로 사용하지 않는다.
5. 브라우저 호환 라이브러리는 해당 프로세스 경로에만 적용한다. 전역 라이브러리 경로 변경으로 해결하지 않는다.
6. 소스 URL·SHA·제공되는 서명·라이선스·레시피·도구 체인·CPU 등급·SDK·패키지 SHA를 연결한다.
   업스트림 서명이 없는 소스는 부재를 기록하고 별도 검증 정책을 적용한다.
7. 빈 빌드 경로에서 필수 패키지를 재생성하고, 완성 아카이브만으로 새 rootfs를 조립한다.
8. 고정 스냅샷으로 새 ISO를 만들고 재추출한 파일·서명·패키지·부팅 구조를 검사한다.

**완료 기준:** 선언한 공급 파일 누락 0건, 설명되지 않은 의존성·파일 소유권 충돌 0건,
구버전 덮어쓰기 0건. 실제 패키지 개수와 인덱스 레코드 수를 구분해 보고한다.
빌더 캐시·VM에서 꺼낸 파일만으로 성공한 결과는 깨끗한 재빌드와 구분한다.
전체 ISO의 바이트 단위 재현성을 확인하기 전에는 이를 보증하지 않는다.

각 버전·CPU·구성의 기존 입력 핀은 바꾸지 않는다. 패키지가 달라지면 새 RC 또는
1.3.N 스냅샷을 등록한다. 날짜별 재생성이나 메모 변경으로 기존 ISO의 검증 상태를 소급 변경하지 않는다.

## 7. UI/UX 완료 기준

| 흐름 | 필수 동작 | 인수 기준 |
|---|---|---|
| 시작·언어 | 설치기 언어와 설치 OS 언어 구분, 실제 지원 구성 안내 | 한국어·영어 화면과 한글 입력 확인, 미번역 필수 오류 없음 |
| 언어·시간 | 로케일·키보드·시간대 선택과 검색, 입력 시험 | 선택값이 계획과 설치 후 설정에 일치 |
| 디스크 | 모델·용량·식별자·사용 상태·기존 배치·설치 후 배치·삭제 범위 표시 | 대상 변경 시 동의 해제, 사용 중 장치 차단, 잘못된 대상은 포맷 전 실패 |
| 네트워크 | 장치 선택, DHCP·고정·오프라인, DNS와 연결 검사의 실제 범위 표시 | 입력 형식 검증과 실제 연결 확인을 구분, 설치 후 이름 변경에도 설정 유지 |
| 계정 | 암호 확인, 표시 전환, 키보드 상태·입력 오류 안내 | 평문 로그·계획 유출 없음, 생성 계정으로 실제 로그인·sudo 가능 |
| 설치 환경 | 서버·GNOME 및 선택 그룹의 목적·공급 여부·예상 공간 안내 | 없는 패키지 선택 차단, 설치 후 GNOME 앱과 선택 집합 일치 |
| 검토 | 카드별 요약·해당 화면 수정·계획 변경 시 재동의 | 다음/뒤로 이동 시 값 보존, 오류 위치로 이동, 변경 전 동의 재사용 금지 |
| 진행·실패 | 단계·패키지 개수·현재 작업·상세 로그·정체 안내·복구 방법 | 정체를 종료로 오판하지 않음, GUI 로그 저장과 민감값 제거, 안전한 종료 경로 제공 |
| 완료 | 설치 버전·결과·로그 위치·미디어 분리·명시적 재부팅 | 자동 재부팅 없음, 실제 재부팅 후 로그인·네트워크·서비스 확인 |
| 운영 화면 | 상태 → 실패 서비스 → 로그/Console → 기존 관리자 → 결과 확인 | 권한 부족·조회 실패를 정상 0으로 표시하지 않음, Polkit와 GNOME 앱 유지 |

설치기는 서버 운영 화면과 색·아이콘·문구를 맞추되 설치 절차의 가독성을 우선한다.
픽셀 스타일은 장식적 폰트나 작은 클릭 영역을 강제하는 근거로 사용하지 않는다.
정식 지원 UI의 라이트/다크·고대비·키보드 탐색을 검사하고, 작은 콘솔 해상도와
확대 배율에서도 필수 버튼·경고가 잘리지 않는지 확인한다. RC 기준 해상도·배율은
0단계에서 고정하며 기본 시험 후보는 1024×768, 1366×768, 1920×1080과 100%·200%다.

사용 중인 왼쪽 화면·호스트 포커스·클립보드를 조작하지 않고 별도 후보 VM과
그 VM의 SSH·가상 입력 경로를 사용한다.

## 8. 업데이트·복구 인수 시험

정상 경로만 통과하면 완료로 판정하지 않는다. 시험은 별도의 빈 디스크·차등 디스크에서
수행하고 기존 VM·원본 데이터에는 실패 상황을 주입하지 않는다.

| 시나리오 | 완료 기준 |
|---|---|
| 서명·변조·누락 | 잘못된 서명·SHA·패키지·의존성·필수 파일은 적용 전에 거부하고 마지막 검증 입력 유지 |
| 정상 업데이트 | 실제 설치된 v1.3 후보에서 다음 후보로 업데이트 후 부팅·계정·SSH·DNS·KI2 DB·GNOME·앱 확인 |
| 용량 부족·통신 중단 | 오류와 변경 범위를 기록하고 사용자 데이터·계정·기존 부팅 경로 보존 |
| 트랜잭션 중단·전원 차단 | 디스크 적용 단계별 격리 시험, DB와 실제 파일의 일치 확인, 자동 또는 문서화한 수동 복구 통과 |
| 커널·initramfs·부트로더 실패 | 이전 정상 커널 또는 복구 미디어로 부팅하고 올바른 root·데이터를 식별하여 서비스 복원 |
| 설정·사용자 데이터 | 사용자 수정 설정의 충돌 처리·백업·복원 정책 확인. 패키지 교체로 사용자 데이터를 초기화하지 않음 |
| 권한·계정 | root 잠금, 사용자 D-Bus·logind·Polkit, SSH 호스트 키·사용자 인증이 업데이트 후 유지 |
| 백업·새 서버 복원 | 포함·제외 범위를 명시하고 새 격리 서버에서 필요한 패키지·ISO·DB·키·서비스 복구 확인 |
| 신뢰 키 교체 | 새·기존 키의 신뢰 전환과 폐기된 키 거절 확인. 개인키가 ISO·공개 저장소·로그에 없음 |

전체 OS 원자적 롤백을 구현했다고 표시하지 않는다. v1.3의 필수 조건은 **실제로 통과한
업데이트·복구 경로**다. 자동 롤백이 없으면 필요한 콘솔·복구 ISO·백업·작업 순서와
복구할 수 없는 경계를 명시한다. 부분 백업을 전체 복원 시험으로 간주하지 않는다.

기존 후보에서 v1.3으로의 인플레이스 업그레이드는 시험한 출발 버전만 지원 목록에 넣는다.
미검증 후보는 데이터 백업 후 신규 설치 경로를 안내한다.

## 9. LTS 지원 기간 제안

### 9.1 권장안: 정식 출시일부터 24개월

- GA일을 `G`로 정하고, 지원 종료일을 `G + 24개월`에 맞춰 명확한 날짜로 공지한다.
- 예를 들어 2026-12-01 출시라면 2028-11-30까지 지원하는 안이다.
  이는 기간 계산 예시이며 출시 일정 약속이 아니다.
- 지원 범위는 승인한 서버·GNOME 구성과 CPU·가상화 플랫폼이다. 실험 기능은 별도다.
- 기간 중 보안·치명적 데이터 손상·설치/부팅/업데이트 회귀를 우선 수정하고
  새 데스크톱·AI 기능의 추가는 억제한다.
- 지원 책임자·대체 담당·빌드/서명 권한·패치 저장소·복구 자원을 0단계에서 지정한다.
  이를 확보하지 못하면 24개월 LTS를 정식으로 선언하지 않는다.

### 9.2 커널과 주요 구성요소 조건

2026-11-16에 확인한 [kernel.org 공식 지원 일정](https://www.kernel.org/category/releases.html)은
Linux 6.1의 예상 종료를 2027년 12월, 6.12와 6.18을 2028년 12월로 표시한다.
이 일정은 예정값이며 변경될 수 있다. KIKI의 자체 패키지에 업스트림 지원이 자동 승계되는 것은 아니다.

따라서 기존 **6.1.187을 고정한 채 24개월 지원을 약속하지 않는다.**

1. 기존 6.1 환경과 ISO는 보존 기준선으로 유지한다.
2. 0단계에서 6.12·6.18 중 드라이버·하이퍼바이저·사용자 공간 호환성과 지원 기간을 비교한다.
3. 정식 종료일까지 보안 수정 공급이 가능한 계열을 RC 전에 선정한다. 정확한 패치 버전·URL·SHA·설정은 별도로 잠근다.
4. 출시 지연으로 선택 계열의 업스트림 예상 종료가 KIKI 종료일보다 빨라지면,
   지원 계열 변경 또는 자체 백포트 책임과 시험 계획을 승인받기 전까지 LTS 출시를 보류한다.

GNOME·GTK·Mesa·브라우저·OpenSSH·암호 라이브러리·컨테이너 런타임도 같은 방식으로
지원표를 만든다. GNOME 50 유지 여부는 보안 수정·의존성 호환성 평가 후 결정하며,
버전 이름을 고정했다는 이유로 보안 수정을 중단하지 않는다. 필요 버전 전환은 별도
후보에서 GNOME 앱 호환성을 확인한 뒤 수행한다.

**대안:** 커널 6.1 유지를 우선한다면 GA부터 12개월 지원을 검토하되, 종료일이
업스트림 예상 종료를 넘지 않아야 한다. 자체 패치 공급 계획 없이 기간만 연장하지 않는다.

### 9.3 유지보수 운영안

| 항목 | 제안 |
|---|---|
| 정기 업데이트 | 월 1회 보안·안정화 묶음. 영향도에 따라 별도 긴급 릴리즈 |
| 긴급 취약점 | 접수 후 2영업일 내 영향 평가 목표. 완화책·시험 상태·공급 예상일을 공지하며 무검증 패치를 급히 승격하지 않음 |
| 업데이트 검증 | 서명·SHA·의존성·지원 플랫폼 설치/업데이트/복구 회귀를 통과한 경우만 안정 채널 승격 |
| 호환성 | 사용자 데이터·설정·KI2 DB·관리자 API 호환성 유지. 불가피한 변경은 이관 절차와 되돌림 조건 공지 |
| 종료 공지 | 종료 6개월·3개월·1개월 전 안내와 백업·이관 경로 제공 |
| 종료 후 | 최종 서명 릴리즈와 증거 보관. 업데이트를 계속 받을 수 있다고 표시하지 않음 |

응답 목표는 운영안이다. 담당·자원이 확정되기 전 외부 SLA로 보증하지 않는다.

## 10. 단계별 산출물과 종료 조건

| 단계 | 산출물 | 다음 단계 진입 조건 |
|---|---|---|
| 0. 계약·보존 기준 확정 | 보존 목록, 지원 매트릭스, C/Go 비교·선택 기록, CPU·커널 결정, LTS 담당·종료일 계산 규칙 | 설명되지 않은 기준선 차이 없음. 지원 제외 항목과 유지보수 책임 승인 |
| 1. 설치기 단일화 | 공식 GUI·계획/TUI·Stage-1 경로, 카탈로그·런타임 명세, 일치 시험 | 대표 설정의 동일 결과, 폴백·비밀값·포맷 전 검증 통과 |
| 2. 공급본 통합 | 전체 소스/패키지 잠금·SDK 명세·서명 스냅샷·깨끗한 rootfs | 실물·서명·의존성·파일 소유권 확인, 오버레이 의존 없이 조립 |
| 3. UI/UX·OS 통합 | 서버·GNOME 구성, 설치/운영 화면, 로그·Console·Polkit·기존 앱 회귀 | 화면별 인수 기준과 로그인 세션·네트워크·권한·재부팅 통과 |
| 4. 업데이트·복구 | 정상/실패/중단 시험 결과, 복구 ISO·백업·키 교체·운영 매뉴얼 | 8절 시나리오 통과 또는 정식 범위 제외가 승인됨. P0 미해결 없음 |
| 5. RC 고정·인수 | 불변 RC 명세, ISO 재추출 검사, Hyper-V·QEMU/KVM 보고서 | 같은 RC ISO로 신규 설치·2회 부팅·실제 GDM 암호 로그인·Wayland·GTK 앱·업데이트/복구 확인 |
| 6. LTS 승인·배포 | 릴리즈 노트, 지원 계약, 서명 산출물·소스·라이선스/SBOM·검증 색인 | 출시 차단 0건, 예외 승인 완료, 담당자 승인 후 안정 채널·태그·양쪽 Git 안내 반영 |

초기 단계 일부 작업은 병행할 수 있지만, 최종 RC는 설치기·패키지·UI·복구 변경이
반영된 동일 공급본으로 다시 검증한다. 중간 변경이 생기면 영향받은 검사와 ISO를 갱신한다.
실기·리소스 확인 전 작업 일수를 확정하거나 자동 출시 일정을 잡지 않는다.

### RC 공통 보고 형식

- 소스 커밋·소스 아카이브 SHA, 빌드 도구/컨테이너/SDK, CPU·커널 설정.
- 공급 스냅샷·패키지별 SHA·서명, ISO SHA, 설치기 구현과 실행 파일 SHA.
- 실제 VM/디스크 식별자, 부팅 ID, 설치 집합과 설치 DB, 테스트 시각·도구 버전.
- 자동 시험과 사람의 화면 확인, 통과·실패·건너뜀·미실행을 각각 구분.
- 확인된 위험·예외·복구 방법·이전 정상 버전과 데이터 호환성.

시험 대상을 찾지 못한 결과, 로그인 화면만 확인한 결과, 직접 커널 부팅 결과를 각각
실제 사용자 로그인·펌웨어 부팅·ISO 신규 설치 통과로 확대 해석하지 않는다.

## 11. 출시 차단 및 변경 통제

다음 중 하나라도 남으면 v1.3 정식 LTS 승격을 중지한다.

- 공식 설치기 구현이나 최종 공급 스냅샷이 불명확함.
- 패키지 누락·서명/SHA 불일치·출처 불명·설명되지 않은 의존성 또는 버전 역행.
- 설치 대상 오인·원본 훼손·평문 비밀값 포함·운영용 시험 암호 사용.
- 지원 환경의 신규 설치·로그인·업데이트·복구 실패 또는 필수 항목 미실행.
- 실제 로그·권한·서비스 상태를 정상으로 오판하는 UI 오류.
- 지원 기간 중 패치 공급 계획이 없는 핵심 구성요소 또는 미지정 유지보수 책임.
- 부분 보호 사본만으로 전체 복구를 완료했다고 표시하는 등 증거와 출시 안내가 다름.

개발은 별도 후보 경로와 새 패키지 release·스냅샷·ISO에서만 진행한다.
기존 설치기·원본 패키지·남은 ISO·GNOME 앱·서명 키·인증 DB는 임의로 삭제하거나 덮어쓰지 않는다.
incident-ai 자동 연동 보류는 별도 재개 지시 전까지 유지한다.
