# KIKI OS 온디바이스 AI 관리 콘솔

KIKI OS 서버 프로필은 부팅 후 `tty1`에 한국어 AI 관리 콘솔을, `tty2`에
독립 복구 셸을 제공합니다. 이 콘솔의 목적은 ISO 설치 이후에도 네트워크,
디스크, 서비스 같은 시스템 관리를 자연어로 계획하고 사용자가 정확한
명령을 승인한 뒤 실행할 수 있게 하는 것입니다.

## 안전 경계

- 명령 종류를 제한하지 않지만 모든 명령은 `argv` 배열로 먼저 표시합니다.
- 사용자가 정확히 `실행`을 입력하기 전에는 변경하지 않습니다.
- 파이프나 리디렉션이 필요하면 `/bin/sh -c` 자체도 화면에 드러납니다.
- 각 명령은 제한 시간 안에 순서대로 실행되며 첫 실패에서 중단됩니다.
- 검증 실패 시 롤백 명령을 다시 표시하고 별도의 `롤백` 확인을 받습니다.
- 승인, 실행 결과, 검증, 롤백은 root 전용 JSONL 로그에 기록됩니다.
- 모델이 멈추거나 잘못된 JSON을 반환해도 `tty2` 복구 셸은 영향을 받지 않습니다.

## 런타임 선택

CPU 기반의 작은 단일 노드 ISO에는 GGUF 양자화 모델과 `llama.cpp`가 적합합니다.
`vLLM`은 GPU 서버용 선택 런타임으로 남기며 기본 ISO 의존성에는 넣지 않습니다.
기본 로컬 API는 OpenAI 호환 `http://127.0.0.1:8080/v1/chat/completions`이고,
모델 별칭은 `kiki-ops`입니다.

기본 ISO에는 한국어를 지원하는 공식 `Qwen2.5-1.5B-Instruct-GGUF`의
`Q4_K_M` 파일을 `/var/lib/kiki/models/kiki-ops.gguf`로 내장합니다. 모델
저장소 커밋, 모델 SHA-256, Apache-2.0 라이선스 파일 SHA-256을 빌드 레시피에
고정하고 라이선스 전문도 시스템에 함께 설치합니다. 다른 모델로 교체할 때는
새 모델의 SHA-256과 재배포 조건을 다시 검토해야 합니다.

## 콘솔 사용

자연어 요청 외에 `/상태`, `/도움말`, `/종료`를 사용할 수 있습니다. 계획을
본 뒤 `수정`을 선택하면 보충 요청으로 새 계획을 만들고, `취소`를 선택하면
감사 로그만 남긴 채 어떤 명령도 실행하지 않습니다.

설정은 `/etc/kiki/ai-console.json`, 감사 로그는 기본적으로
`/var/log/kiki/ai-console.jsonl`입니다. 원격 OpenAI 호환 서버를 쓸 때만
`endpoint`, `model`, `api_key_file`을 변경하십시오.
