# AI 메타정보·업데이트 계획과 라이브 패치 시험 준비

2026-11-01 구현. 기존 v1.0 태그와 정식 릴리즈는 변경하지 않는다.

## 사용 방법

패키지 메타정보 편집 화면의 **AI 메타정보 제안·업데이트 계획**으로 이동한다. 패키지 이름이 전달된다. 새 패키지 등록 화면에서도 AI 보조 도구로 이동할 수 있다. 업데이트 후보 준비 화면에는 AI 계획 링크가 있다.

메타정보 제안은 카탈로그의 설명·라이선스·분류·소스·의존성과 편집본 번호를 고정한다. 응답은 필드 길이와 JSON 스키마를 검사한다. 현재 값과 제안을 비교·수정한 뒤 변경 사유를 입력하고 기존 메타정보 저장 절차로 반영한다. 카탈로그가 변경되었으면 기존 리비전 검사로 충돌을 반환한다. 모델 응답을 명령이나 HTML로 실행하지 않는다. 라이선스 원문 확인은 별도 검토 사항이다. 아직 README·라이선스 원문을 자동 수집하지 않으며, 카탈로그만을 근거로 삼는다.

업데이트 계획은 카탈로그에서 계산한 전이 의존 영향과 사용자 입력 대상 버전을 설명한다. 대상 버전 존재·ABI 호환성·CVE 해결 여부를 확정하지 않는다. 모델 입력의 영향 목록은 최대 40개이며 전체 계산 결과는 보고서에 보존한다. 실제 빌드·승격은 기존 업데이트 검증을 거친다. 기준 스냅샷의 실제 후보 계획과 AI 참고 계획은 구분한다.

AI는 요청할 때만 기존 로컬 `kiki-ops` 모델을 사용한다. 응답은 기록되고 자동 적용되지 않는다. 계획 입력은 6KB를 넘으면 잘라서 사실을 잃는 대신 거부한다. 새 작업의 출력 한도는 4096토큰이다.

## 커널 라이브 패치

`/kernel-livepatch`는 저장된 설치 커널 설정의 해시와 필수 설정을 확인하고 시험 VM 검증 절차를 제공한다. 실제 실행 커널 지원 판정이나 샘플 패치 컴파일·적용 시험은 아직 하지 않는다. 현재 보존 설정은 `CONFIG_LIVEPATCH`, `CONFIG_FUNCTION_TRACER`, `CONFIG_DYNAMIC_FTRACE_WITH_REGS`가 활성화되어 있지 않다. 서명과 디버그 정보도 준비가 필요하다.

실제 시험 전 실행 커널과 소스·설정·컴파일러·심볼 일치를 확인하고 전용 VM에서 모듈 빌드, 대상 불일치 거부, 서명, 전환 완료, 부하, 제거 가능 여부, 재부팅 복구를 검증해야 한다. 이번 변경은 커널·ISO·VM을 변경하지 않는다.

## 검증

- 로컬 LLM 실제 메타정보 JSON·업데이트 계획 응답 생성 통과.
- 계획·HTTP 검증 5개, AI 기존 회귀 4개, CI·인증 회귀 67개 통과.
- Linux 업데이트·릴리즈 회귀 52개 통과. Windows의 같은 검사는 OpenSSL·파일 잠금 조건으로 실패하여 Linux에서 확인했다.
- 카탈로그 회귀 16개 중 12개 통과, 환경 조건 4개 제외.
- 실제 모델 응답을 사용한 패키지 링크·이름 전달·비교 저장 폼·커널 미지원 표시와 데스크톱/모바일 화면·스크립트 오류 확인 통과.
- 운영 반영은 실행 중 빌드가 없는 경우에만 진행하며 기존 파일·인증 이미지를 백업하고 시작 실패 시 복원한다.
- 운영 HTTP 백엔드에서 실제 모델을 호출하는 메타정보·계획 요청이 모두 통과했다. 검토 폼만 생성하고 카탈로그에는 저장하지 않았다.

자동 백업 일정, 실행 중 빌드 취소, 통합 승격 대시보드는 이번 AI 기능 구현 범위에 포함하지 않는다.
