# KIKI OS v1.3 LTS 0단계 — 보존·설치기·공급 기준·지원 범위 점검

점검일: 2026-11-16 (한국 시간)

후속 승인: 사용자가 C/GTK4 주력, x86-64-v2 최소 CPU 목표, 6.12 LTS 우선 평가,
24개월 지원 기준을 확정하고 별도 후보의 1단계 구현을 지시했다.
[1단계 기록](kiki-os-v1.3-lts-stage1-installer-20261116.ko.md)을 함께 참조한다.
아래는 승인 전 읽기 전용 조사 당시의 기록이며, 커널 최종 패치·CPU 실증·유지보수 담당 지정은 여전히 별도다.

**판정: 읽기 전용 실물 점검과 기술 권고 정리 완료. 0단계의 전체 종료 조건은 아직 미충족이다.**
유지보수 담당·지원 기간 승인, CPU 호환성 판정 방법과 커널 최종 선정이 남았다.
제품 구현·컴파일·패키징·ISO 생성·서비스 재시작·Git 동기화/푸시는 하지 않았다.
incident-ai 자동 연동은 계속 보류한다. [최종 계획서](kiki-os-v1.3-lts-final-plan.ko.md)의
0단계 실행 기록이며, 1단계 구현이나 정식 LTS 승인을 의미하지 않는다.

## 1. 이번에 실행한 범위

- 기존 보존 목록을 기준으로 설치기·원본 패키지·남은 ISO 등 전체 SHA-256 재검사.
- 인덱스·공개키 핀, 서명된 메타데이터, 패키지 실물 수, 주요 버전과 공급 경로 비교.
- C/GTK와 Go/gotk4 소스 및 보관 패키지의 실제 런타임 명세 확인.
- 원격 build-server의 작업·컨테이너·마운트·보존 파일·Git 입력·호스트 CPU/커널 읽기 조회.
- Hyper-V 보존 VM의 ID·전원 상태·디스크 연결만 조회. VM을 시작하거나 화면에 입력하지 않음.
- kernel.org의 업스트림 예상 지원 종료일 확인. 커널 소스 다운로드·재빌드·교체는 하지 않음.

새 파일은 본 문서와 `artifacts/kiki-v1.3-lts/20261116-stage0`의 점검 증거에만 작성했다.
비밀번호·개인키·인증 DB 내용을 결과에 포함하지 않았고, 왼쪽 화면·호스트 포커스·클립보드를 조작하지 않았다.

### 0단계 기술 권고

**공식 v1.3 GUI의 단일화 기준은 C/GTK4로 정리한다.** 최근 GNOME 경로뿐 아니라
GA 기반 release 28의 실물도 C여서 설치 환경·카탈로그 기준을 이어가기 좋다.
Go 계획 생성기/TUI와 Stage-1은 유지하며 Go GUI 소스·기존 ISO는 삭제하지 않는다.

다만 C 구현이 모든 항목에서 앞선 것은 아니다. 1단계에서 비동기 계획 생성·시간 제한,
설정 변경 시 재동의, 기존 요청 충돌 방지, 단계별 오류 위치 안내를 인수 기준으로 보강한다.
일반 빌더 기본값·gotk 전용 refresh 경로·오래된 문서를 함께 정리해야 단일화가 끝난다.
이번에는 기본값이나 코드·레시피를 바꾸지 않았다. 새로운 GUI 인수 시험도 실행하지 않았다.

전부 `package-baselines.json`에 기록했다. 구버전 전체 폴더를 최신 VM에 적용하면 안 된다.

### 공급 파일 추적 결과

- 최신 목표 236개 중 **220개**는 이번 로컬 전체 SHA 검사에서 일치하는 파일을 찾았다.
- 나머지 **16개**는 서버의 기존 보호 명세에서 찾고 실제 파일 SHA를 다시 계산해 일치 확인했다.
- 서버 보호 명세에는 236개 모두의 현재 실물 경로가 있다. 이 중 220개는 이전 보호 SHA와
  이번 메타데이터 대조 기반이며, 서버 쪽 236개를 모두 새로 해시했다고 표시하지 않는다.
- 따라서 로컬 220개 + 서버 추가 16개의 조합으로 목표 SHA 공급 위치를 확보했다.
  이는 새 저장소 조립·서명·최종 의존성·파일 소유권 검증을 끝냈다는 뜻은 아니다.

서버에서 추가 확인한 16종:

`acl`, `base-files`, `hyperv-daemons`, `ki2ctl`, `kiki-desktop-defaults`,
`kiki-installer-gtk`, `kiki-installer-tui`, `kiki-security-content`, `kiki-vm-tools`,
`libxslt`, `linux`, `openscap`, `openssh`, `qemu-guest-agent`, `readline`, `xmlsec`.

**통합 방침:** 최신 GA/운영 목표의 패키지별 SHA를 우선 비교 기준으로 삼고,
실물 공급 경로를 고정한 새 독립 저장소를 후속 단계에서 조립한다. 그 뒤 지원 커널과
v1.3 수정 패키지를 새 release로 반영한다. 현재 236개 목록 자체를 최종 v1.3 잠금으로
선언하지 않는다. 이번에 패키지 복사·복원·재빌드·인덱스 변경은 하지 않았다.

Windows에 OpenSSL 실행 파일이 없어 첫 범용 검증 함수의 false 결과는 서명 불량으로
판정하지 않았다. 기존 canonical payload·key ID 규칙과 Ed25519를 사용하는 cryptography로
공개키와 서명을 재검증했다. 검사 도구와 결과는 별도 증거에 기록했다.

## 5. CPU 지원 범위

| 항목 | 확인·권고 |
|---|---|
| 기존 명세 | 세 인덱스의 모든 레코드에 `cpu_profile` 명시 없음. 현재 관리 도구도 기존 x86_64를 ISA 미분류로 취급 |
| 과거 빌드 기록 | 네이티브 SDK/커널 기록에 x86-64-v2 요구가 있음. 일부 실제 앱 빌드 스크립트는 `-march` 없이 SDK를 재사용하므로 하나의 플래그로 전체 바이너리를 증명할 수 없음 |
| 목표 권고 | 서버·GNOME 구성 모두 **x86-64-v2를 최소 기능 후보**로 삼고 v1 기본 호환은 약속하지 않음 |
| 정식 표시 조건 | C/C++·Rust·Go·어셈블리·공식 바이너리·전이 라이브러리의 요구 조사 + v2 기능으로 제한한 VM에서 설치/로그인/앱 시험 |
| v3/v4 | 대상별 전체 패키지·제한 CPU VM 증거 확보 전 비활성 유지 |
| Intel/AMD | 제품 세대명이 아니라 기능 등급으로 지원. 특정 제조사로 한정하지 않음 |

이번 서버 호스트는 KVM의 Intel Ivy Bridge 계열 모델, 4 vCPU, x86_64로 조회됐다.
이는 빌드 호스트의 노출 정보이며 대상 패키지의 최소 CPU 호환 시험이 아니다.
Hyper-V의 일반 CPU 호환 옵션만으로 정확한 ISA 등급이 제한됐다고 가정하지 않는다.

**미확정:** v2가 전체 설치 집합을 수용하는지, 제한 VM 시험을 어떤 CPU 모델/플래그로
재현할지. 이번에 CPU 플래그·컴파일러·기존 바이너리를 바꾸거나 VM을 실행하지 않았다.

## 6. 커널 지원 범위

| 계열 | 역할 | 이번 판정 |
|---|---|---|
| 6.1.187 | 보존 ISO·GA/후보의 현재 기준 | 원본 유지. 장기 지원 목표를 충족한다고 새로 승인하지 않음 |
| 6.12 LTS | **v1.3 우선 평가 후보** | 보존 드라이버·설정·사용자 공간과 비교 후 결정. 정확한 패치 버전 미잠금 |
| 6.18 LTS | 대안 평가 후보 | 추가 장치·지원 요구 또는 6.12 시험 결과에 따라 비교. 자동 업그레이드하지 않음 |

6.12를 우선 평가하는 것은 기존 6.1에서의 전환 범위를 제한하려는 기술 권고이며,
실제 호환성·안전성·성능을 검증했다는 뜻이 아니다. 지원 기간만으로 두 계열의 우열을 정하지 않는다.

보존 설정에는 x86_64·generic CPU·UEFI/GPT·virtio block·Hyper-V storage 등 설정이 있다.
후속 비교는 Hyper-V 저장소/네트워크/KVP/VSS·DRM, virtio, 파일시스템, namespace/cgroup,
보안 옵션과 커널·모듈·헤더·initramfs·기존 커널 복구 경로를 함께 다룬다.
빌드 서버 자체의 Rocky 커널 `5.14.0-687.12.1.el9_8.x86_64`와 KIKI 대상 커널을 혼동하지 않는다.

공식 지원 일정은 아래 LTS 항목에 근거를 남겼다. 커널 소스 URL·SHA·서명·설정·도구 체인의
정확한 잠금은 커널 후보 결정 후 별도 입력 검토 단계에서 수행한다. 이번에 준비됐다고 표시하지 않는다.

## 7. LTS 지원 계약 제안과 미결정 사항

### 지원 범위 권고

- KIKI OS 전체 1.3.0 LTS, GA부터 **24개월** 유지보수.
- 서버 기본 구성과 GNOME 운영 구성을 동일 코어 기준으로 관리.
- 검증 플랫폼은 Hyper-V Gen2·QEMU/KVM UEFI, Secure Boot 끄기를 우선 계약으로 제안.
- GNOME·GDM/Wayland·기존 GNOME 앱·작은 운영 앱은 유지한다. 별도 셸 포크는 제외.
- 업데이트·복구는 실제 통과한 출발 버전·대상 구성만 지원한다. 전체 OS 원자적 롤백은 보증하지 않는다.
- incident-ai 수동 연결은 유지하고 자동 문맥 수신·전송·조치 연동은 계속 보류한다.
- 물리 장치·Wi-Fi·Secure Boot·BIOS 설치·고급 스토리지·v3/v4는 별도 인수 전 지원으로 표시하지 않는다.
- Kubernetes 역할은 실제 클러스터 시험 결과를 별도 승인한 경우만 해당 보증 범위에 포함한다.

### 지원 기간 조건

2026-11-16 조회한 [kernel.org 공식 일정](https://www.kernel.org/category/releases.html)은
6.1의 예상 종료를 2027년 12월, 6.12·6.18의 예상 종료를 2028년 12월로 표시한다.
예정일은 변경 가능하며 KIKI가 자동으로 같은 지원을 받는 것은 아니다.
GA일부터 24개월이 이 기간을 넘으면 자체 보안 백포트·지원 계열 전환 계획을 먼저 확보해야 한다.

GNOME·GTK·Mesa·브라우저·OpenSSH·암호 라이브러리·컨테이너 런타임도 각각
업스트림 지원과 KIKI 패치 책임을 연결해야 한다. GNOME 50 유지와 24개월 보안 지원을
같은 의미로 취급하지 않는다. 이번에는 이 구성요소 전체의 지원 종료일을 확정하지 않았다.

| 미결정 항목 | 필요한 결정·증거 | 현재 상태 |
|---|---|---|
| GA일·정확한 EOL | GA일과 24개월 계산 규칙을 적용한 날짜 | 미정. 출시일을 임의로 만들지 않음 |
| 지원 기간 승인 | 24개월 권고 수용 또는 6.1 유지 시 12개월 대안 | 권고 상태 |
| 유지보수 책임 | 보안 접수·패치·서명·시험 담당 및 대체 담당 | 미지정. 사용자 개인이나 계정을 임의로 책임자로 지정하지 않음 |
| 컴포넌트 지원표 | 업스트림 종료·자체 백포트·계열 전환·회귀 자원 | 후속 검토 필요 |
| 최소 CPU 계약 | v2 제한 시험 방법·지원 표시 | 후보, 아직 인증 아님 |
| 정식 커널 | 계열·정확한 패치·입력 잠금·호환 인수 | 우선 평가 후보만 선정 |

권고 정책은 월별 안정화 묶음, 긴급 취약점 영향 평가 목표 2영업일, 종료 6·3·1개월 전
공지다. 인력·자원·책임 확정 전 SLA로 보증하지 않는다.
